# Implementation Plan: Genitractor Sources & Import

## Overview

This plan implements the design in `design.md` (Components 1–9, Correctness Properties 1–9, Testing Strategy) against the running app under `app/` on branch `feat/catalog-audit-v5`. The work is **Python** (backend: `app/server.py`, `app/sources/genius.py`, `app/jobs.py`, `app/excel.py`) and **JavaScript/HTML** (frontend: `app/static/genitractor.js`, `app/static/genitractor.html`, `app/static/app.js`, `app/static/index.html`). Property-based tests use `hypothesis`; golden/parity and integration tests use `pytest`; frontend behavior is covered by example tests.

Sequencing minimizes breakage by building in this order: (1) a test harness plus a **pre-removal Chartporter golden baseline** captured before any column removal, (2) pure `genius.py` foundations, (3) `get_socials` balanced matching, (4) `_geni_worker` outcome/record wiring, (5) export, (6) feed UI, (7) Chartporter social-column removal validated against the golden baseline, (8) the Import button/modal, (9) the import-from-Chartporter endpoint, and (10) a final regression/preservation checkpoint for Requirement 10 and Property 9.

Preservation call-outs are embedded in the relevant tasks: audit/classification byte-parity (Req 7), export filter parity (Req 7/10.9), and prior-branch fixes (Req 10: backoff `[2,4,8,16,32]`, pause 5s/250, `geni_clear`, snapshot fields, timer resume, cross-status running-only, `pct` NaN guard, DOM cap 200, plain CSV).

## Notes

- Tasks marked with `*` are optional test sub-tasks and can be skipped for a faster MVP; core implementation tasks are never optional.
- Each task references specific files/functions from `design.md`, the Correctness Property it exercises, and the requirement clauses it satisfies.
- **Ordering rationale:** pure/backend foundations first (genius.py → get_socials → _geni_worker → export) so each layer is independently verifiable before the next consumes it; the feed UI follows the stable `contact_done` payload; Chartporter removal is gated by the **pre-removal golden baseline captured in Task 1.2** so parity can be proven; the Import feature is last because it reuses the now-stable enqueue path; the final checkpoint validates Requirement 10 and Property 9.
- **Preservation checkpoints** are embedded where audit/classification (Req 7), export filter parity (Req 7/10.9), and prior-branch fixes (Req 10) are at risk — see the call-outs in Tasks 3.1, 4.1, 5.1, 8.2, 8.5, 11.1, and 12.x.

Critical path: `1.1 → 2.1 → 2.3 → 3.1 → 4.1 → 5.1 → 11.1 → 11.2 → 11.4`.
